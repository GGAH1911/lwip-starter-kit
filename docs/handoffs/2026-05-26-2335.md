## Decisions & rationale

- **Hook installation via `git config core.hooksPath hooks`** rather than `cp hooks/pre-commit .git/hooks/`. The worktree's `.git` is a file pointing to the actual gitdir; copying into it would fail. The config approach also versions the hook and propagates across worktrees.
- **`LWIP_Specification.md` left untouched** despite being v1.2 and now contradicting v1.4/v1.5 (still describes "JIT scripts at every shutdown"). User only requested README rewrite. Flagged as pending — see Open questions.
- **Handoffs in their own folder, not appended to `log.md`.** `log.md` is a one-line operations ledger (ingest/prune/triage). Handoffs are narrative session records — different cadence, different reader (next session's Boot Gate vs. historical audit).
- **Handoffs are versioned in git** (unlike `state.json` which is gitignored). They need to be human-readable history, and the next session must be able to read them after a `git clone`.
- **Handoffs are exempt from 0-Isolation / 0-Gap / 100%-Lineage** via `EXCLUDE_TOP`. They are not mesh nodes — they reference mesh nodes. Forcing them to obey mesh rules would require hub-registering every handoff, which is circular noise.
- **Handoff also exempt from `flat_dir` check** — same `EXCLUDE_TOP` mechanism. Many handoffs is expected and shouldn't trigger restructuring.
- **Handoff is mandatory in both shutdown branches.** Trigger-gating exists to skip *heavy LLM grooming* (multi-node restructuring). One write per session is cheap and high-leverage. Skipping it defeats the entire point of v1.5.
