## What was done

**Added `tests/test_lwip_audit.py`** — stdlib `unittest` only (no pip,
matching the kit's dependency-free promise). 11 tests, loaded via
`importlib` because the auditor filename is hyphenated. Each test builds a
throwaway repo tree in a temp dir and points the auditor's module path globals
at it, then calls the unit functions directly (no subprocess, no git).

Coverage:
- `is_node` classification (hubs/index/log/readme/inbox/handoffs/archive
  excluded; concepts/foundations/gaps included).
- isolation vs weak-isolation (meaningful vs navigational inbound).
- missing vs broken lineage.
- congestion (over/under the hub cap).
- flat-directory and inbox-backlog alerts.
- **hub-edge extraction** — the explicit regression guard for the bug the
  first ingest found (hubs must be scanned for edges though exempt as nodes).
- pipe-annotated edge type (`[[x|supports]]`).
- node→node links do NOT clear 0-Isolation (only hub links do).
- excluded subtrees contribute no edges.
- `addresses_gap` edge capture.

Run with `python3 -m unittest discover -s tests`. Added a Tests section to
README.

**Two real inconsistencies caught by the suite on its first run:**

1. **Doc vs impl (gaps).** `docs/gaps/README.md` claimed an `addresses_gap`
   link from a resolver node "automatically satisfies 0-Isolation via the
   resolver." It doesn't — `collect_hub_links` only counts inbound links
   **from hubs**, consistently for every node type. Corrected the README:
   gaps clear 0-Isolation via a hub link (typically `core` while open);
   `addresses_gap` is an additional semantic edge recorded in `edges.jsonl`,
   not an isolation-clearer.
2. **DEFAULTS out of sync.** `lwip-audit.py`'s `DEFAULTS.meaningful_link_types`
   still listed only the five v1.4 types — `addresses_gap` had been added to
   `lwip.config.yaml` but not to the script's built-in defaults. So in any
   environment without the config file present, `addresses_gap` would be
   silently treated as navigational. Added it to DEFAULTS with a sync note.

**Verification:** 11/11 tests pass; full-repo `python3 tools/lwip-audit.py`
still `hard_alerts: 0`, 29 edges.

## Decisions & rationale

- **stdlib unittest, not pytest.** The kit promises no pip installs; the test
  must honor that or it undermines the kit's own constraint.
- **Patch module globals rather than refactor the auditor to take path args.**
  Lower-risk: no change to the shipped auditor's signature/behavior, the test
  just redirects ROOT/DOCS/etc. for the duration of each test.
- **Kept the "0-Isolation = from a hub" rule rather than making `addresses_gap`
  special.** A consistent rule (every node, including gaps, is anchored by a
  hub) is simpler than a per-type exception. The resolver is itself hub-linked,
  so a resolved gap stays transitively reachable; no need to weaken the rule.
- **No CI workflow added.** Considered a GitHub Actions runner, but kept this
  change minimal — documented the run command instead. CI is a possible
  follow-up, not required for a stdlib test you can run in one line.
