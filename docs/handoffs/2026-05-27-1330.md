**Bug found and fixed (the whole point of the test).** The first non-trivial
input immediately exposed a defect in v1.6's `extract_all_edges`: it reused
`EXCLUDE_TOP`, which excludes `hubs/` (correct for `is_node`, since a hub isn't
a spoke). But hubs are the *primary source of typed edges*, so the auditor was
skipping them entirely — all 14 initial edges came out `navigational`, zero
meaningful. Fixed by introducing a separate `EXCLUDE_EDGES_TOP =
{00_inbox, .lwip, handoffs, archive}` that keeps hubs in scope for edge
extraction. After the fix: 6 meaningful hub edges (depends/core×3/supports×2)
captured correctly; 29 edges total at close.

## Decisions & rationale

- **Source choice.** Used our own comparison analysis rather than inventing a
  throwaway domain. It's genuine knowledge the human spent many sessions on,
  and ingesting it is exactly what LWIP is for. Slightly meta (the wiki's first
  content is about the wiki's design space) but honest and lineage-clean.
- **Lineage via raw/sources/.** External URLs can't satisfy the auditor's
  `(ROOT / source).exists()` check, so the fetched facts were saved as Tier 1
  files and every node's `sources:` points at a real path. This is the correct
  LWIP pattern: raw clips are immutable ground truth, mesh nodes synthesize
  from them.
- **EXCLUDE_TOP vs EXCLUDE_EDGES_TOP split.** Two genuinely different
  questions were conflated: "is this file a spoke node?" (hubs: no) vs. "should
  we read this file's outbound links?" (hubs: yes, they're the main source).
  Archive is excluded as an edge *source* because a `contradicts` edge *to* an
  archived page comes from a live hub, which is now scanned.
- **No version bump for the fix.** The protocol is still v1.6; this is a tooling
  bug fix to the auditor, not a protocol change.
